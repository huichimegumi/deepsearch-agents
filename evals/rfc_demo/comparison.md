# RFC 问答开发集：是否启用重排

使用 v1 开发集里没有显式指定章节的九题（D02 单列为定点取证演示，不参与对照）。每题只构建一个混合检索候选池；B 保持融合顺序，C 用 BGE 打分再取前八。两组调用同一个应用 Writer、同一模型及预算，交替运行顺序。先确认九题都真正执行了 CPU 重排，再开始生成。最多 18 次请求，不重试，不读保留题。

预定选择规则：只有正确答案数增加、没有新增关键错误，且 CPU 重排耗时中位数不超过 2 秒，才考虑把重排接入演示。检索召回提高但答案未改善时保留混合检索。证据锚点及正确性分开统计，关键错误按原文核验，格式失败与拒答分别保留。

## 实测与决定

BGE 权重快照 `2cfc18c9415c912f9d8155881c133215df768a70`，通过 Hugging Face CLI 取得，实际推理使用 FastEmbed 的 CPU 后端。运行限制为 CPU 0–7，首次模型加载包含在对应首题的时间里。生成用 `qwen-flash`，未使用第二个模型判分。参考答案已由 Codex 对照原文复核，以下是同一执行者的事后审阅，不是独立人工判分。题目与参考未改动。

| 指标 | B 混合检索 | C 加重排 |
| --- | ---: | ---: |
| 正确（含适当拒答）／部分／错误／交付失败 | 5 / 2 / 2 / 0 | 3 / 1 / 3 / 2 |
| 证据锚点命中（7 道可回答题） | 5/15 | 6/15 |
| 逐题平均锚点 Recall@8 | 42.86% | 47.62% |
| 检索耗时中位数 | 0.459 s | 7.939 s |
| 检索＋生成耗时中位数 | 2.788 s | 10.060 s |
| 实际请求／供应商返回的总 tokens | 9 / 10,629 | 9 / 8,684 |

重排额外耗时的逐题中位数 **7.494 s**。每组两道范围外题均正确拒答。锚点是固定文字证据单元；同一章节的其他段落也可能支持正确作答，D04 就是例子。时延是本机顺序测量，不是并发服务性能。

**保留 B 作为演示路线。** 重排只多找到一个标注锚点，正确交付更少，且耗时超过预定上限。此次没有修提示或重跑，防止围绕这几题继续扩大开发。两组都出现有出处但读错规范的情况，引用链接不能当作正确性保证。
