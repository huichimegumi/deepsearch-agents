# RFC 演示 BM25 对照

RFC 路径用 BM25 对固定索引中的段落排序，分词复用入库时的 `lexicalize`。参数为 `k1=1.2`、`b=0.75`。向量和词法各取前 24 个候选，沿用 RRF（常数 60），再按排名展开前五个不同章节，每节最多 2,200 字符。明确指定章节的查询继续直接定位。通用知识库仍用原 PostgreSQL 词法路径。

## 开发题检索

相同索引与应用入口，分别用 PostgreSQL 和 BM25 作为词法候选来源。两个版本都启用章节扩展。下表只统计七道普通可回答开发题。

| 指标 | 向量 + PostgreSQL | 向量 + BM25 |
| --- | ---: | ---: |
| 候选段落命中（去重） | 9/15 | 13/15 |
| 页面证据命中（去重） | 6/15 | 15/15 |
| 候选段落命中（按评分要点计） | 9/16 | 14/16 |
| 页面证据命中（按评分要点计） | 6/16 | 16/16 |
| 页面覆盖所有标注出处的题数 | 3/7 | 7/7 |

D07 两个评分要点共用一个锚点，因此逐项计有 16 项，去重后有 15 个。候选池按原段落匹配，页面按章节展开后的实际文字匹配。候选池可以先命中同一章节的其他段落，展开后才出现标注原句。D06、D07、D08、D09 的展示覆盖提高。指定章节的 D02 两边均展示 2/3 个锚点。两道资料不足题仅展示候选，未调用 Writer。[PostgreSQL 逐题数据](sources.bm25-baseline.json) · [BM25 逐题数据](sources.bm25.json)

## 同证据 Writer 对照

两种模型接收同一份 BM25 证据包和提示，每题各一次请求，不启用格式重试。沿用九道非定点开发题。内容由 Codex 对照冻结参考和引用原文审阅。

| 指标 | Qwen Flash | Qwen3.8 Max 0902 |
| --- | ---: | ---: |
| 内容正确，含两道适当拒答 | 6/9 | 7/9 |
| 部分回答 | 2/9 | 2/9 |
| 格式导致交付失败 | 1/9 | 0/9 |
| Writer 耗时中位数 | 1.63 秒 | 3.18 秒 |
| 请求 / 供应商返回 Token | 9 / 20,629 | 9 / 20,468 |

D06 的强比较与任一标签匹配、D07 的缓存时长和新鲜度，两组均回答正确。D04 两组都遗漏非负整数限制，D09 两组都给出弱比较和更新标头，但未明确说明保留已存响应正文，因此按冻结参考评为部分回答。D08 是两组差异，Flash 草稿包含正确的主要区分，但有未附引用的陈述，格式校验拒绝交付，Max 通过。本次交付差异只有一道，默认 Writer 保留现有配置。[逐题 Writer 指标](writers.bm25.json)

## 冻结后复查

在提交 `5304ebb` 上，对先前已使用过的五道保留题做纯检索复查。四道可回答题共有九个去重锚点，候选段落命中 7/9，实际页面命中 **8/9**，3/4 道覆盖全部标注出处。生成请求为 **0**。这组题曾用于一次问答验证，本次仅衡量检索展示，作为复查记录。[冻结复查汇总](sources.bm25-recheck.json)

## 复现

使用已有 CPU 索引，在仓库根目录运行。每次指定新目录，第三条会调用模型。

```sh
CUDA_VISIBLE_DEVICES=-1 HF_HUB_OFFLINE=1 uv run python -m evals.rfc_demo.check_sources --postgres NEW_POSTGRES_DIR
CUDA_VISIBLE_DEVICES=-1 HF_HUB_OFFLINE=1 uv run python -m evals.rfc_demo.check_sources NEW_BM25_DIR
CUDA_VISIBLE_DEVICES=-1 HF_HUB_OFFLINE=1 uv run python -m evals.rfc_demo.compare_writers NEW_WRITER_DIR
```

持有本机五题原始包时，`check_sources --sealed NEW_RECHECK_DIR` 可在提交后的检索版本上复查。仅输出汇总，原始材料保留在本地运行目录。
