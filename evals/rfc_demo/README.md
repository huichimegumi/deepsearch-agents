# HTTP 规范问答：小型评测 v1

范围与 [界面演示](../../docs/development/rfc-demo-stage-1.md) 一致：固定 RFC 9110 / 9111 的编号章节，单轮问答。题集用于区分检索、作答和引用问题，不评估整个研究 Agent。

- 开发集 **10 题**，前 3 题是已有演示题。包括事实、多要点、数字、跨文档、比较和两道资料不足题。D02 指定章节，用于检查定点取证与写作；D09 不提供章节，用于检查自然问法的跨文档检索。D02 不计入下一阶段的重排配对比较。
- 保留集 **5 题**，同一语料中的新问题。题目与评分参考只留在本机 `evals/results/rfc-demo-v1-sealed/`，分别保存；Git 只提交数量与哈希。目录需另行备份，克隆仓库不会恢复这些文件。它不是外部盲测，也不是跨语料泛化测试。
- 模型输入只能读取 `questions.json` 中的题号与问题；答案要点、锚点和关键错误单独保存在 `references.json`。开发阶段不读取、不运行保留题。版本与评分口径冻结后再运行一次保留集。
- 参考由 Codex 对照原文起草。开发集已按用户授权由 Codex 复核，结果见[配对对照](comparison.md)；未完成独立人工判分，保留题未运行。若人工发现参考错误，留存修改理由并生成新锁；已经用于修复的题不得继续作为保留题。

## 离线预检

```bash
uv run python -m evals.rfc_demo.verify
```

校验两份 RFC 的官方快照与演示索引输入哈希、开发集文件哈希、题号与评分参考对应关系，以及每个锚点是否出现在指定章节。若缺少快照，可用演示导入脚本准备两份文件。已有第 1 阶段索引的环境，升级后重启 worker 并在知识库页面对两份示例文档点一次「重新索引」：此前解析器会把 RFC 语法记号中的井号误认作标题。仅在维护或最终验证保留集时加 `--sealed`；该选项仍只做离线校验，不调用模型，也不打印题目。

## 计分口径

每个必答点分别标记覆盖／未覆盖；表述可不同，关键条件必须保留。正确需覆盖全部要点、无关键错误；有实质要点但遗漏且无关键错误，记部分正确；有关键错误、答非所问，或对可回答题没有提供任何必答点，记错误。资料不足题单列，明确说明范围且不编造才正确。运行失败或超时单列，保留在全题分母中。

证据召回按已确认锚点分别计数；没有锚点的资料不足题不进入召回分母。锚点只用于可复现的检索计数，未命中不排除另有有效证据。人工另外核对引用是否支持主张；有效链接不能代替语义支持。记录每题耗时、实际请求与供应商返回的 token，未提供则标明缺失。报告逐题和配对差异，不合并成单一总分。

本阶段验证：两份文档重建索引后，开发集 19/19、保留集 9/9 锚点都能在标有对应章节的已就绪段落中找到；这是可检索性检查，不是 Recall@k 实测。题包字节改动会被预检拒绝，解析及问答回归测试 14 项通过。本阶段没有调用生成模型。
