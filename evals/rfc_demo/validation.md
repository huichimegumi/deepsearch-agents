# 演示版保留题验证

冻结 `ccab4ec` 的应用问答路径：固定 RFC 9110/9111 索引、混合检索、不启用重排、同一应用 Writer、qwen-flash。五道同语料保留题各运行一次，最多五次请求，运行失败仍计入。只读取问题包；所有输出落盘并核对索引后，才打开参考评分。不用保留题调整检索、提示或阈值。

发布定位预先约定：至少 4/5 正确（含适当拒答）且无关键错误，才以带出处的短问答作为推荐演示；否则把检索和原文定位作为推荐体验，生成问答仅保留为实验选项。分数仅适用于本套小样本。

## 一次性运行结果

冻结应用提交 `ccab4ecb20d47f08118fe17c2bb4ca77c1bbd1f6`，CPU、qwen-flash，未启用重排。五题全数完成运行：四题交付带链接的回答，一题提示证据不足，没有执行失败。共 **5 次请求、6,533 个供应商报告 token**，检索加生成耗时中位数 **2.71 秒**。

可回答题的 **9 个标注锚点有 7 个进入上下文，7 个被引用**。离线核对中，两道回答命中主要预期检查且命中全部标注出处；范围外题按预期拒答。另外两道回答未能核实每个要点都有直接引用支持。锚点和规则匹配只是证据检查，不是完整语义评分：未把这些题判为内容错误，也未宣称得到 4/5 或 5/5 的答案正确率。原始题目、回答、参考和证据均留在本机。

**发布决定：推荐 HTTP 规范查证，生成问答保留为实验。** 查证模式复用原检索，展示最多五条实际片段及原文章节，不调用 Writer。它是发布范围调整，不是保留集上的新分数。没有调整问答提示或检索排序，也没有重跑保留题。

本机的一次性入口为 `python -m evals.rfc_demo.validate_demo`，要求私有题包和固定索引，运行前后核对索引指纹，已有运行目录时拒绝再次执行。公开仓库未分发保留题；开发集仍可使用已有对照入口复现方法。历史 Hybrid SQL 记录不变。

查证模式另用公开示例在 Chromium 中验证：同一次指定两份 RFC 的章节，页面展示五段原文片段、两份 RFC 的章节链接，后台记录 **0 次 Writer 请求**。这是功能验证，与保留题分开。17 项相关回归、前端 TypeScript/Vite 构建、Ruff 与 diff 检查通过。保留题仍只运行一次；原有 GitHub Actions 设置保持关闭。
