# E11-3：固定的小样本、后端纠错与停止

GitHub Actions 在开发前已通过仓库 permissions API 关闭，enabled=false；此阶段不运行云端 CI。固定协议为 e11-canary.lock.json，复用既有 canary 执行器，模型改用 MetricSelection 和单字段 SourceExcerpt。E10 原始结果保留，不把不同报告协议混成同一成绩。

三项控制为一题辅助 SQL、两题旧证据报告，各最多一请求。实际 **3 次 qwen-flash 请求、25234 预留 token**，不是账单 token 数；没有 DeepSeek、GPU、付费搜索、模型重试或新验证样本。

冻结代码的原始结果为 **1/3**：

- SQL 工具参数已可解析为选择对象，但包含未绑定文本值，后端拒绝；没有执行 SQL，未得到可比较结果。不能宣称 SQL 推理已经正确，也不能归类成 JSON 失败。
- DABStep 报告交付两张完整表和一段通过原文检查的摘录，无绑定错误。
- Hybrid 报告保留一张完整表；模型明确返回空摘录，原代码把它当作错误。

复核发现后一项是后端契约矛盾：SourceExcerpt 的空字符串代表没有相关材料，不能等同于格式错误。此阶段随后离线修正两处接口：合法弃答不产生事实也不报协议错误；唯一、精确匹配已提供观测值的文本可解析到原绑定键，不接受大小写猜测、模糊匹配或新造值。未放松非空摘录的原文与完整性检查。

原始候选、请求账本、冻结 manifest 和修复前后端源码副本保留在忽略目录。修复后的代码只回放已保存候选，没有再次调用模型：SQL 仍因未提供的值被拒绝；两份报告均可保留完整表格，后一份明确标记 excerpt_abstained，均保持 partial。**这不是修复后的新模型成绩，不重写原始 1/3。** 引文一致性不代表任务覆盖或来源真实。

公开结果见 evals/reports/e11-3-canary.json；完整输出位于 evals/results/e11-3-canary 和 evals/results/e11-3-offline-replay。没有将问题、原文、业务常量、参考 SQL 或生成 SQL 提交到仓库。

继续门槛未满足，因此整组组件、完整开发集和独立验证均未运行。e11-components.lock.json 固定了未来整组八项报告和六项 SQL 控制，要求全部 canary 项通过且源码一致才允许准备；门槛仍为报告 8/8、辅助 SQL 至少 4/6，不能用顶层自报通过数放行。当前修复后源码也已不同于 canary，不能拿旧结果直接放行。

当前进展是后端公开指标、实际锚点、来源绑定和合法弃答都有离线检查；仍未证明选择器能可靠选择正确字段、值、方向和输出。下一轮应继续收敛选择器输入与允许值，先做离线错误分析，不追加本轮调用、不自动换模型。端到端最近的严格开发集成绩仍为 E8 的 0/8。
