# E8-3：报告范围与可恢复小批评分

报告的数值 fact 增加 entity、period、unit 和 section；相同 metric 在不同实体/期间/单位下可并存，完全相同范围的重复 metric 仍拒绝。数值必须与原始证据路径精确绑定。分节渲染保留旧三列表兼容性。长报告允许更多独立主张，但自适应 Writer 要求最多 24 条简洁 claims、16 条 facts；文本/Web 中的数字可用有来源的自然语言主张表达，不强行塞入数字字段。格式或绑定错误至多一次修复，无新工具、无额外总预算。

评分版本 e8.1 使用最多四项的独立批次，每批只返回按顺序排列的固定长度分数，索引由后端拥有。检查项覆盖率与逐条主张支持率分别计算；错误批次保留并使任务不能通过，合法低分不会重试。评分 manifest 固定题目、原始结果、评分代码、报告 schema 的摘要，每批落盘，可恢复而不重复付费调用。旧 E7/v4 评分代码和成绩保持不变。

Hybrid 增加独立只读重跑：参考 SQL 必须与冻结参考行一致，实际 SQL 使用当时记录的参数重执行；比较保留行关联、重复行和字符串/数值类型，允许列别名/顺序变化或具名必要列投影，避免用别名差异判错。多来源方向要求真实成功步骤的依赖链，不能只凭模型宣称。运行完成、回答完整、来源齐全、数值绑定、引用存在、覆盖率至少 0.8、主张支持率至少 0.9，以及 Hybrid SQL/方向检查必须同时满足。

受控校准使用八个已有人工构造样例，非新验证题：DeepSeek 8/8 符合预期；Qwen 5/8，其中两例解析失败、一例误接受缺失年份。这不是自然报告的人类一致性结论。详见 evals/reports/e8-3-calibration.json。主评分使用 DeepSeek，不通过重试筛选模型输出。

统一入口增加 `python -m scripts.evaluate e8-score --run RUN --inputs INPUT_DIR --output SCORE_DIR` 与 `e8-gate --run RUN --score SCORE_DIR --output GATE_JSON`。`check` 包括 trace、证据存储、自适应和 E8 协议的离线测试，在现有 Linux/Windows CPU CI 中执行。

开发门槛使用 E8-0 冻结的八道已暴露题；不能视为泛化评测。旧 bounded 流程重新生成的基线与 adaptive 使用相同请求/工具/时间上限。除控制流以外，公开 schema 语义适配、证据视图和报告合约也有变化，因此不把差异单独归因于模型。新验证只在至少 6/8 严格通过且引用/预算合规后准备，最多一次集中修复与复查。

本阶段真实结果：旧流程严格 0/8、平均覆盖率 20.2%；首次 adaptive 也为 0/8、平均覆盖率 28.9%，两者各 6 completed、2 delivery_invalid。首次 adaptive 有三个任务的主张评分批次错误：模型误评整份报告而非当前批次，错误批次未截取或重试，任务不能通过。原始记录保留；这说明受控八样例未覆盖多批长报告协议，不能宣称评分已可靠。下一阶段集中修复会隔离批次输入并重新校准，保留本版成绩。所有引用 ID 合法、额度合规，但质量门槛未达到。759 项离线全量测试通过、6 项跳过；统一跨平台检查 48 项通过。
