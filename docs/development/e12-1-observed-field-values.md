# E12-1：实际字段值与来源绑定

GitHub Actions 再次查询确认为 enabled=false；不改工作流或启用云端 CI。本阶段不请求模型、不下载新数据，不使用 GPU。

新增 observe_values，从实际允许的 SQLite 数据库读取 DISTINCT 文本候选，保留每项 SQL Evidence ID、字段引用和实际值。候选只表示数据库中观察到该字段值，不证明它是问题所指实体。连续数值阈值仍需来自问题或公开定义，不能由枚举候选证明业务条件正确。

最多扫描 64 个字段、每字段 8 项、最终 120 项，SQL 观测有总时间限制。优先相关指标所在表、问题明确提到的值及完整的小枚举，再分配高基数字段预览。任何预算、字段或行截断都明确标记 incomplete；缺少候选不代表值不存在。输入来源仅为问题、公开定义和数据库，没有参考 SQL 或参考字面量。

BoundValue 新增可选 field_ref。选择器既检查候选键的所属字段，也按字段查找唯一精确文本匹配；同一文本出现在多个字段时不再混为全局绑定。错误字段、未知文本和模糊匹配继续拒绝。原有带独立来源的非字段绑定兼容保留。

验证：实际观测/指标选择/原查询编译器共 19 passed；Ruff 与格式检查通过。覆盖高基数字段问题命中优先、完整性标记、总预算、跨字段同名值、错误字段候选拒绝和未观测值拒绝。测试通过不代表 benchmark 任务已通过。
