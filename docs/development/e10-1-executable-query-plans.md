# E10-1：有限查询计划与完整语义上下文

`describe` 的前五条相关知识现在按依赖关系展开，最多 4000 token。每个根定义及其传递依赖整体纳入，缺失、循环或预算超限时拒绝该根并给出原因，不提供看似完整的半个公式。对六道实际开发题离线检查：提供 6/6/6/7/7/8 条定义，缺失直接依赖均为零，没有根被预算拒绝。这里只验证上下文完整性，没有新的模型成绩。

新增共享 `app/research/query_plan.py`。模型声明按依赖顺序排列的表达式、输出、筛选、分组、排序和连接，后端生成带绑定值的 SQLite SQL。支持算术、比较、条件表达式、普通聚合和少量明确函数；除法强制实数，零分母返回 NULL。声明的 groups/rows 必须与聚合对应，未分组的输出/排序被拒绝。连接限定为数据库实际声明的单列唯一目标键，避免加入一对多表扩大原始行数。字段必须存在、输出别名唯一、表达式无前向/循环引用，展开长度受限。

外部值带 exact/pattern 模式及 source_ref，编译器拒绝将 pattern 值用于等号；不通过修改筛选强行得到非空结果。source_ref 保留来源声明，不代表已独立核验该来源或实体映射。

边界：这不是通用 SQL 编译器，不支持窗口、子查询、自连接、复合连接键和任意函数；不支持的任务必须失败或先做明确分解，不能悄悄回退自由 SQL。编译器保证声明计划的执行约束，不能证明模型选对了业务公式、筛选、实体或完整任务范围。现有 SQLIntent 和默认研究路径保留；新执行入口为 execute_plan，等待组件门槛后才接入默认流程。

验证：查询计划与原 SQLIntent 测试共 14 passed，覆盖多实体/多期间净额汇总、连接唯一性、分组错误拒绝、绑定注入、通配匹配、实数除法与零分母、语义依赖闭包/缺失/循环/预算。Ruff 通过。零 API、DeepSeek、GPU 调用；E9 成绩和门槛不变。
