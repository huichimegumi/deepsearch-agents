# E10-2：后端安排报告，隔离逐条主张错误

compact_report 的新 scalar 模式由后端安排最多两节和八张完整结果表，不再请求模型生成提纲。模型工具 SectionDraft 只有两个短主张、逗号分隔引用、引用范围及一项限制，全部为标量字段。旧模式显式保留用于已有存档协议，默认产品研究流程没有改动。

新视图在完整结果全部可见时才给出 table_ref；截断结果或上下文省略过行的完整表只提供行级观察引用。records 范围只接受可见 eN，complete_result 只接受明确暴露的完整 table_ref。后端不把模型声明的 scope 当作语义蕴含证明，之后仍需独立检查整条主张是否得到支持。

每条主张独立验证。错误引用保留原始输出和具体原因，拒绝该条；已通过的其他主张、原始行和后端表格不丢失。不截短超限引用、不猜测修改非法 JSON。模型请求失败时继续保留表格和其他章节。后端初始 answerability 为 partial：协议交付不等于所有任务部分已经回答，不沿用模型自称 answered。

验证：报告组件测试 8 passed，包含完整表/预览的不同引用权限、未知行引用隔离、超限引用不截断、禁止嵌套额外字段，以及后端表格保留。离线对八题旧材料组装后端章节，全部完整结果表均保留且单元格绑定检查通过；这不是模型报告通过率。零模型调用。下一阶段先冻结三项诊断 canary（一个 SQL 非空不匹配案例、两个报告失败案例），不直接重跑整组。
