# E12-2：相同公开输入上的简洁 SQL 基线

新增 grounded_context，复用公开 MetricRegistry、字段实际观测和已有编译器。按问题与指标词项相关度选最多两张表，保留字段 ID、简短语义、公开定义和实际候选值；表和候选列表均明确为有限范围，不代表完整数据库知识。没有读取参考答案或参考常量。

MetricRelations 将所选表的全部原始行及后端计算的指标投影到内存 rN 关系。每表最多 10000 行、64 列，源查询有时间限制；超限拒绝，不能把截断数据当完整数据。compile_plan 暴露经过同一校验的投影片段，原有表达式、粒度、字段和只读约束没有绕过。源数据库事务读取，原表不会被修改。

模型 SQL 仅在这些内存关系上运行。SELECT/CTE、常见聚合/字符串/窗口函数允许，写入、ATTACH、原数据库表、系统表和未批准函数拒绝；另设执行时间和输出行数限制。模型仍可能选错条件/方向，必须独立比较实际结果。

选择器和 SQL 基线共享完全相同的生成端 payload，路由只决定输出接口与执行方式。基线可以表达现有选择器尚不支持的 SQL 组合，二者不保证表达能力相同；这种差异正是对照要观察的内容。不能把基线通过直接归为模型能力提升。

验证：关系/取值/原编译器共 20 passed，覆盖公开公式数值、全行复制、预算超限拒绝、原表不可访问、写入/附加库/危险函数拒绝、重复输出列和超时。实际两道已暴露 SQL→Search 开发题的数据上下文可离线构建，没有模型、GPU 或新样本调用。Ruff 通过，Actions 保持关闭。
