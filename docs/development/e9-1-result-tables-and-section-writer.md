# E9-1：结果表、短引用与分节报告

沿用原 EvidenceStore、请求预算和追踪，新增共享 app/research/compact_report.py；尚未升级默认 legacy/experimental adaptive 路径。新报告组件把 SQL 结果按查询和参数分组存档，保留完整的实际返回行、原始 Evidence ID、列顺序与完整性标志。来源视图增加文件名/页码/标题等有限 metadata，仍计入同一个 12k token 上限。

模型使用 e1/e2 行或文档引用、t1/t2 表引用；表级 Evidence 由后端从实际返回行构建，保留 derived_from。选择的完整表由后端复制到最终报告，不让模型重抄数字、行关联和长 ID。表的每个单元格、行 Evidence 和空结果都再次校验；截断查询不能作为完整最终表。叙述分为最多两节，每节最多 1800 输出 token；提纲最多 1400，总计至多三个请求，不靠扩大旧单次输出限制解决问题。一节错误保留已经完成的表和其他有引用主张，标记 partial，不能声称 answered。

Qwen 原型控制暴露了两个协议设计问题：嵌套提纲会生成错位工具参数 JSON，长表 hash ID 会少抄字符。因此最终提纲改为固定扁平字段，表 ID 改为简单编号；拒绝猜测修补 JSON 或截掉超出数组元素。trace 现在保存 invalid_tool_calls 和完整原始 AI 消息，解析器为空时也不再丢失失败参数。

## 实际验证及边界

最后协议回放同一八题已收集证据，不重新取证、不读参考答案、不消费新题：

- 后端固定选择、单元格/行绑定与短引用往返：8/8。
- Qwen 在该材料上无段落协议/绑定错误的交付：5/8。两道 DABStep 的结果表均保存；其中一道仍因叙述引用不完整表而有失败段落。另两题有模型段落 schema 错误。
- 组件 5/8 不是任务通过率；没有检查这些旧材料是否足够回答问题，也不把模型自称 answered 当成完整性证明。E8 严格 0/8 保持不变。
- 开发过程中共五版控制原型：前两版各完成八题、后两版各检查前三题、最终版完整八题。所有版本保留，报告列出每版分母和结果，以最后版为主；不从各版挑最好题合成。
- 所有原型总计 64 次已发请求，账本模型均 qwen-flash、DeepSeek 零次。预留 token 是输入估计加输出上限，不是实际账单金额。

完整摘要见 evals/reports/e9-1-report-components.json。全量离线测试 772 passed、6 skipped，跨平台统一入口 61 项通过；包含 200 行结果无损复制、篡改拒绝、截断结果拒绝、出处/短引用、有一节失败仍保留数据、完整保存非法工具参数等回归。

报告数值传递这一确定性组件已通过，但 Qwen 文本交付门槛尚未通过，本层不再追加模型回放。六例 SQL 控制不依赖 Writer，可独立定位执行前的语义问题；这是 E9-2 的组件诊断，不是绕过报告门槛进入端到端。E9-3/新验证必须同时满足报告与 SQL 门槛，当前仍禁止。
