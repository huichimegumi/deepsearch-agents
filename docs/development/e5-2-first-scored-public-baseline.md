# E5.2 首份公开语料完整评分基线

日期：2026-11-01。正式运行 ID：`benchmark_v3_20261101T044148Z_7644c548`。

## 口径与结果

从已锁定的 DABStep Research 选择 8 题（2 dev、6 个曾在早期开发中暴露的 holdout）。同一只读 SQLite 快照和公开商户手册供生成器使用，参考统计和检查表分数只在评分阶段使用。旧个人电脑上的 PDF 未参与。Hybrid 三题另属跨源工程 smoke，不能混入这 8 题的分母，也不能把 DABStep 已暴露 holdout 当成新的独立测试。

简单基线按固定、只读的 8 类 SQL 查询获取真实数据，覆盖总体、商户、ACI、卡组织、月份、缺失值、商户属性和费率规则概览；每题得到 61 条带稳定 Evidence ID 的记录，再用 `deepseek-flash` 一次写成报告。评测温度为 0，输出上限 8,000 token，SDK 隐式重试关闭，免费 DuckDuckGo 锁定，GPU 禁用。生成器没有接收参考答案或参考 SQL。

8/8 题达到终态且均为 `completed`；中位耗时 28.0 秒，样本 p95 为 34.3 秒。逐题检查表覆盖率平均 0.847；按预先固定的“覆盖 ≥0.80、证据支持覆盖 ≥0.75、引用 ID 全合法”口径，模型裁判暂定通过 5/8。引用 ID 合法率逐题均为 1.00；这是身份校验，不代表每条引用的语义都正确。生成器共记录 104,424 token，三次重复裁判共 323,659 token。三次裁判取中位数；例如 041 题三次覆盖分为 0.9、0.4、0.5，显示模型裁判并不稳定。此分数不是人工准确率、不是官方 DABStep 排行榜成绩。

失败集中在 003、020、041：当前 SQL 摘要没有逐笔费用匹配、费用总额及可审计的节省额计算。报告明确承认这些数字未计算，避免凭规则和交易量捏造金额；评分仍按原检查表扣分。后续应增加确定性费用引擎的聚合 Evidence，而不是放宽 rubric。

原 agent 对照已启动，但首题 `dabstep_research_002` 在 106.797 秒以 `degraded` 结束。Trace 显示 17 次模型调用、540,619 输入 token、17,559 输出 token、20 次 SQL 查询，失败原因为 `llm_call_limit`；该数字超过配置的 16 次逻辑调用上限。其报告并非空白：49 个引用 ID 均能解析，使用同一裁判独立复评三次，要点覆盖为 0.833、0.917、1.000；但按冻结的端到端通过口径，运行降级仍不得算通过。为了避免把相同的资源浪费扩展到余下 7 题，批次在下一题执行中被主动中止，未把未运行题目记为成功或失败。本阶段没有完整原 agent 对照分数；下一阶段须先实现发送前的调用和 token 准入，再以相同预算续跑。

## 评分与可复现性

`evals.score_v3` 独立读取 worker 输出，按冻结检查表逐项评“完整、部分、缺失”和是否由 SQL Evidence/商户手册支持；DeepSeek 裁判每题重复三次并取中位数。超时、异常和降级均保留在任务分母。支持/矛盾/漏答三种已知小例子的真实裁判校准结果分别是 `full+supported`、`missing+unsupported`、`missing+unsupported`。规则分数、三次裁判结果、引用校验、运行/评分器源码哈希及模型实际 token 用量都已复制到 `evals/reports/e5-2-dabstep-simple-deepseek-*`；原始回答与 Evidence 存在忽略的 `evals/results/`，未推送。

开发中还做过一次未固定温度的探索运行，虽然也是 8/8 完成和 5/8 暂定通过，但不与正式运行合并或宣称重复验证。原因是发现 LangChain 将 `max_tokens` 翻译成 `max_completion_tokens`，而 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)规定的是 `max_tokens`。适配器现已转换字段；16-token 真实请求返回 `finish_reason=length`、恰好 16 输出 token。正式运行在此修复之后启动，8 题均未达到 8,000-token 上限。

当前限制：没有人工复核；同模型担任生成器与裁判；已暴露题集不能证明独立泛化；旧 agent 的实际 HTTP attempt/全局 token 预算尚未在发送前强制；Windows 实机清理测试尚未运行。下一个可比较实验必须先修预算，而不是继续消耗未受限的原 agent 调用。
