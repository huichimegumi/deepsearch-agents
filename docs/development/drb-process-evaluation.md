# DRB 过程评测与并行 Web 复测

## 归档轨迹

以下过程数据来自原始 DuckDuckGo 实验的全部 16 题。Token 来自已记录的模型响应。旧轨迹的模型调用计数未覆盖每个网络子代理的所有请求，应按可见计数理解。A 的基线工件提供查询规划与写作的用量和总耗时。

| 指标 | A 单轮 | C deep_report | D thorough |
| --- | ---: | ---: | ---: |
| 正常完成 | 16/16 | 2/16 | 7/16 |
| 耗时中位数（秒） | 36.8 | 117.1 | 180.25 |
| 可见模型调用 | 32 | 158 | 188 |
| 每题输入 Token 中位数 | 3,794 | 82,654 | 90,536 |
| 子代理派发 | — | 19 | 22 |
| 记录到的网页查询 / 重复查询 | — | 143 / 9 | 251 / 33 |
| 独立抓取页（逐题加总） | — | 103 | 169 |
| 收集证据 / 进入 Claim / 实际引用 | — | 103 / 62 / 60 | 172 / 69 / 67 |
| 研究阶段产物缺失 / 退回 | — | 14 / 1 | 8 / 1 |

C 的 97 次主管工具调用中，36 次写待办、9 次列目录、8 次文件匹配。另有 8 次文件读取。主管阶段中位耗时 87.62 秒，简报 5.16 秒、压缩 9.99 秒、写作 17.03 秒。D 的四个阶段分别为 4.56、148.54、10.61 和 15.48 秒。各阶段中位数单独计算。D 多收集 69 条证据，报告多引用 7 条；按记录计，报告引用覆盖从 C 的 58.3% 变为 D 的 39.0%。引用 ID 覆盖度衡量可追溯性，引用是否支持具体陈述仍需内容审核。

复算入口为 `python -m evals.drb_osodt.process_report ARCHIVE OUTPUT_JSON`。当前实现汇总阶段耗时、产物与运行状态、调用数、工具分布、Token、证据漏斗、重复查询和失效原因。对于旧 A 组没有记录的中间指标，保留为空。

## 闭卷对照

同样 15 题，向 A 的 Writer 传入空来源列表。Qwen Flash、温度 0、输出上限 8,000，沿用原 OSODT 设置。生成 15 份报告，搜索 0 次。

| 同题对照 | OSODT 内容均分 |
| --- | ---: |
| A 单轮检索 | 6.510 |
| 闭卷 Writer | 6.962 |

闭卷均分高 0.451，逐题 12 胜、3 负。在这批题和单次运行的设置下，加入归档搜索结果没有带来更高的 OSODT 内容分。因此复测会同时汇报用量、完成率与可追溯证据覆盖。闭卷报告的事实正确性和引用支持未单独评估。

## 请求路径

`RESEARCH_WORKFLOW=parallel_web` 与 API 的 `sources: ["web"]` 一起选择并行路径。评测入口用 `run_agent --research-mode parallel_web`。上传、本地限定与明确非网页证据请求继续使用已有来源路径。

1. 研究简报以结构化输出提供子问题。后端去重并按档位、剩余查询、页面和请求预算分配子代理。默认复测档位为 `deep_report`。
2. 每个子代理只有网页查询工具。每个最多三次模型调用和两次搜索，搜索固定尝试抓取正文。各自有独立份额，查询额度发送前扣除，搜索返回后统一登记已抓取页面与证据。
3. 压缩阶段从登记证据生成带 ID 的 Claim。Writer 接收简报、Claim 包和有字符上限的原文清单，并要求标明未找到检索来源的内容。
4. 交付校验移除未知引用标记，保留报告结构。未知引用和缺少引用被记录为降级。引用 ID 校验仅确认是否指向已登记的证据。

架构图与预算设计见 [并行研究设计](parallel-research-design.md)。在线搜索存在时效与结果波动，复测用于观察此次改动在同一批任务上的行为。
