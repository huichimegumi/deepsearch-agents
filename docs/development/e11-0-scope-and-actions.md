# E11-0：先关闭 Actions，再冻结实现范围

按用户要求，在开发前调用仓库 Actions permissions API 设置 enabled=false，并重新查询确认关闭。已有 runs 均 completed，没有运行任务需要取消。保留工作流文件，不通过提交再开启 Actions；之后每阶段只做本地验证和 commit/push。

离线入口：`python -m evals.diagnostics.coverage_e11 --output evals/reports/e11-0-coverage.json`。只发布参考查询的语法类别、案例 ID 和哈希，不发布问题、SQL、表名、公式或业务常量。参考语法不是唯一正确实现；例如 top-1 可以不用 ROW_NUMBER。

六题的需求范围归纳为：两道 search_to_sql 要求实体定位及同组比较/分档汇总；两道 sql_to_search 要求公开指标、类别约束、排序及名称整理；两道 parallel 还涉及跨表指标和距离排序/组均值。E10 的通用表达式 DAG 不支持完整范围，且真实控制未产生可执行计划。

下一步复用 E10 编译器，由后端从公开知识的数学定义提取有限公式，保留原始定义哈希及依赖；模型只选字段、指标、筛选、排序等。增加通用的实体锚点查询、同组筛选和分档聚合。首批覆盖单表任务；跨表派生指标及组均值距离仍显式不支持，不能拿指标注册数量当作题目通过数。

报告先由后端输出实际结果及来源。模型不再填写引用或引用范围；若需要文字，只对一个固定来源做受约束的摘录，后端验证原文一致性并绑定来源。自由解释留作未验证候选，不能直接当作已支持事实。

阶段：E11-1 指标和小型选择接口；E11-2 后端报告；E11-3 一次冻结的 Qwen 小样本，再按原组件门槛决定是否扩大。仍要求报告 8/8、辅助 SQL 至少 4/6 后才能完整开发；严格开发至少 6/8 且覆盖各 Hybrid 方向后才能独立验证。辅助常量控制不能代替真实 Web↔SQL 依赖。CPU、Qwen 优先，无 DeepSeek。各阶段单独 commit 并 push。
