# E8-4：一次集中修复与有条件验证

E8-3 的 0/8 未达到 6/8 门槛。按预先规则，只允许一次集中修复、一次整组复查，不提前读取新验证题。

## 本次修复

- 已读 Evidence ID 在下一轮有界视图中优先，read_evidence 的 query 用于寻找长文本内的相关片段；全文仍不可变、原始路径不变、总视图仍不超过 12k token。解决“工具返回全文、下一轮又只看相同默认摘录”的断层。
- 决策输入明确剩余动作和尚无成功查询的请求来源，提示优先计算多个请求指标而不是连续拉取大量预览行。
- 一次 Writer 修复带上 prior_report 和精确绑定问题，保留有支持的内容，不能通过新增工具、虚构引用或吞掉错误伪装成功。请求、工具、时间总预算保持冻结。
- 评分 e8.2 的主张批次只包含当前最多四条主张及其引用原文，不再附带整份报告的其他主张；显式传入批次长度。覆盖率仍评整份报告。错误原样保留，不截断评分数组。
- Hybrid 方向审计明确排除 read_evidence：读取旧网页证据不能充当一次新的 SQL→Web 查询。门槛和覆盖/支持标准不变。这是审计实现修正，不把先前 e8.1 的成绩静默覆盖。

e8.2 对旧基线、首次 adaptive、最终复查分别评分到独立目录；两份既有研究不重新生成。e8.1 原始成绩与失败批次留存。这个重新评分是协议修正后的版本对齐，不是研究重跑，也不从同一版本多次评分中挑高分。

## 验证范围

增加跨批次主张隔离、长记录片段定位/替换、旧证据读取不冒充新 Web 查询、Writer 修复看到原候选且不新增工具的回归测试。离线全量 762 passed、6 skipped（新 Writer 回归另行通过）；统一跨平台入口继续包括全部 E8 测试。

校准新增八主张分两批的受控报告，DeepSeek 9/9 符合预期、Qwen 7/9；Qwen 有一次解析失败、一次误接受。长报告样例两模型均通过。受控报告不等于自然任务正确率，最终开发评分另行统计解析失败。

复现方法见 [E8 runbook](e8-evaluation-runbook.md)。HTTP smoke 使用显式 adaptive 工作流和实际 DeepSeek/SQLite 或免费 Web；身份与会话存储隔离替换，结果只证明该路径的检索/交付，不是完整部署和语义验收。

## 最终开发结果与停止决定

| 冻结八题，统一 e8.2 评分 | completed | 其他终态 | 严格通过 | 评分有错误的任务 | Hybrid SQL 匹配 |
| --- | ---: | --- | ---: | ---: | ---: |
| bounded 基线 | 6 | 2 delivery_invalid | 0/8 | 1 | 0/6 |
| 首次 adaptive | 6 | 2 delivery_invalid | 0/8 | 0 | 0/6 |
| 集中修复后唯一复查 | 6 | 2 error | 0/8 | 0 | 0/6 |

复查引用 ID 全部有效、请求/工具/token/时间额度合规；但六题 insufficient_evidence、两题 partial。忽略交付状态、完整性标签和 SQL/方向门槛，仅看内容覆盖率 >=0.8 且支持率 >=0.9，三组也都没有通过题。因此不能把失败只解释为保守标签或评分结构故障。

两道 DABStep 的 Writer 及其一次修复均达到输出上限（finish_reason=length），未产生完整可解析结构；原始响应留存。Hybrid 虽可执行多步查询与实际 Web 检索，但独立结果仍未匹配冻结参考 SQL。复查工具报错任务降至一个，并没有转换为任务质量成功；不把技术修补宣称为评测性能改善。

新版评分修复了首次 adaptive 的三个主张批次错误。旧基线 e8.2 仍有一个覆盖率批次返回了错误长度，保留未知分数与失败，不重试。评分 summary 的 mean_coverage 对未知覆盖率填零，只能作保守诊断，不能作完全观测的准确率比较。受控校准 9/9 也不足以保证自然报告评分可靠。

**门槛未达到：不准备、不运行新验证集。** 本轮到此停止研究迭代，不通过更换样本、提高预算或继续修补凑出通过率。E7 原始评分、E8-3 首次成绩与本轮独立版本对齐成绩均保留。最终摘要为 evals/reports/e8-4-recheck.json，另有 e8-4-baseline.json、e8-4-first-development.json 和 e8-4-calibration.json。

后续若开展新一轮开发，应先解决长报告输出协议（例如后端映射短引用、按问题分节组装，仍保持总预算）、SQL 语义与聚合结果的完整性，以及少量自然报告人工审计。当前证据不支持“只换掉 Qwen 就能解决”，也不支持立刻扩大 benchmark 样本。这里记录后续方向，本轮未额外执行。

实际 API smoke 两路通过：SQL 返回 item_count=3，3 个模型请求；Web 实际取得 2 条 Evidence、交付 5 条主张，6 个请求；HTTP 都为 200、runtime completed，各保存一条 assistant 消息。Web 未做语义验收，不能抵消开发题零通过。结果见 evals/reports/e8-4-api-smoke.json。全程 CPU，未使用 GPU。
