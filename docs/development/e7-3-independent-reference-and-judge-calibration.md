# E7-3：独立参考审计、双裁判校准与匿名复核

评分器独立于应用取证，完整接收公开 checklist/参考；应用仅接收原问题、官方 hint 和真实数据。Hybrid 的 12 个冻结参考 SQL 在只读 SQLite 上均可执行，计算值与已发布 sql_output 全部一致；没有更换坏题。执行使用 SQLite authorizer、只读连接、5 秒进度截止和 1000 行上限，避免词法拦截把字符串中的 update 误判成写操作。对实际执行 SQL 重新计算并比较结果多重集，同时核对方向：Web→SQL 需绑定父 Web 证据，SQL→Web 需对应 SQL 结果进入实际 Web 查询，parallel 需两个来源实际取证。别名忽略、列位置保留，大小写/空白和十进制规范化，细节随结果公开；这不是任意表格语义等价证明。

新增 checkpoint 评分和严格输入/源码摘要，裁判错误持久保留，恢复不重复已判题。主裁判 DeepSeek，独立 Qwen 仅在每类预选两个 ID 上审计，不覆盖主分数。公开报告只含任务 ID、数值指标和错误代码，不重新发布 Hybrid 解密原题/答案/裁判原文。DRB 保留公开细则的加权覆盖分，也列统一 checklist 分，不称官方 RACE/FACT。空拒答没有引用支持率，不把它记作 100%；看覆盖和可回答性机械门槛。

八类自编控制候选含正确回答、错误事实、错引已知 ID、缺引、漏答、把事实藏入 limitations、正确限定拒答及错误拒答。初始 Qwen 将复合声明拆成多个索引，6/8 无效；错误不算成功拒绝。增加显式编号对象后校准两模型共 16 次：DeepSeek 8/8，Qwen 7/8，无格式错误。Qwen 错误接受“事实对但引用来源错”的候选，故独立审计仅为分歧提示，不能替代证据审查或人工。保留首轮与修正轮结果，不继续追该候选改裁判。

E7-2 五个公开开发报告的首次内容评分均未通过严格门槛：DABStep 是 partial/覆盖缺失，Hybrid 包括实体条件、依赖与证据不足。运行完成率不能解释成质量通过率；不再修执行链以追这五题成绩。开发评分的原始 checkpoint 留在本地，后续新评分版本不覆盖旧产物。冻结验证仍未运行。
