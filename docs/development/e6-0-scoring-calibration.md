# E6-0：v4 评分及真实校准

v3 成绩保留原样。新增 `evals.scoring_v4` 和应用通用的 `ResearchReport` 合约：生成报告以声明、数值及来源路径交付。评分器独立核对任务参考数值、每个数值到实际证据字段的绑定、引用身份、必需来源及可回答性；截断和运行失败不能通过。裁判保留 Evidence 的 source/locator/content，并逐项检查要点与被引用原文是否支持完整声明。数值参考只在评分器中出现。任意自由文本的数值仍需语义审阅，机械数值检查范围明确限定为结构化 facts。

修正多次评分的聚合定义：每个指标独立取中位数；v3 采用证据支持排序后选代表回复，其另一个指标未必是中位数。v4 不覆盖历史成绩。未记录的生成器用量为 null，并单列缺失数，不能解释成零 token。

裁判每次回复原子保存；中断续跑复用已完成回复；输入、裁判指令、评分源码及预算摘要不一致时拒绝续跑。每题完成即保存进度。裁判采用独立的发送前请求账本，默认上限 100 次、估算预留 1M token，不启用 SDK 自动重试；已失败的裁判检查点也保留，重新尝试可在新输出目录离线执行，无需重跑研究。

真实校准命令：`python -m evals.calibrate_v4 --output evals/results/e6-0-calibration-v4`。四组公开可见的合成事件由独立 SQLite COUNT 核对，每组生成正确、错误数字、虚构引用、缺引、城市矛盾、输出截断六种候选，共 24 个。DeepSeek 实际裁判：4/4 正确候选接受、20/20 错误候选拒绝，裁判错误 0；请求上限 30，预留 token 上限 150k。源数据可由脚本完整重建，结果位于 `evals/reports/e6-0-*`。这是一组受控校准，尚不能保证复杂自然报告中的所有错误都能被识别。

验证：全套 727 passed、6 skipped，Ruff 通过；包含独立中位数、数值/引用/截断拦截、中断后不重复已完成裁判、配置变化拒绝续跑。全程 CPU，无网页搜索。下一阶段将报告合约和预算接入实际应用，而非把 benchmark 名称放入应用逻辑。
